# 危机预警模块实现方案

## Context（为什么做这个）

用户在做一个 Spring Boot 4.1.0 + Vue 3 的 AI 心理健康助手，已实现用户认证、知识库、情绪日记、AI 心理疏导对话、后台数据分析。用户主要学后端、前端是弱项，希望增加一个**后端亮点足、面试可讲**的扩展模块。选择"危机预警模块"——自动检测用户日记中的高危情绪，调用 AI 做深度分析，通知管理员并给用户推送相关科普文章。

核心价值：定时任务 + 规则引擎 + AI 同步调用 + 邮件通知 + 事务管理，覆盖后端多个技术点。

---

## 一、关键设计决策（已与 Plan agent 论证）

### 1. 双轨制而非纯定时扫描
**问题**：原方案"凌晨 2:00 批量扫描"对危机预警是事后通报——用户白天写自杀日记要 16 小时后才预警。

**方案**：双轨制
- **实时轨（主）**：在 `EmotionDiaryService.create()` 日记入库后立即调用规则检测，命中高危立即触发 AI 分析 + 通知。这才是"预警"。
- **批量轨（兜底）**：凌晨 2:00 定时任务补扫漏网 + 聚合每日高危趋势生成报告。

> **简化选项**：如果工作量过大，可只做实时轨（更简单，省去定时任务+去重+并发锁的复杂度），批量轨作为后续扩展点留接口。本方案默认实现双轨制。

### 2. AI 调用单独建纯净 ChatClient
**问题**：现有 `open-ai` ChatClient 带默认人设"心理疏导师"和 `MessageChatMemoryAdvisor`，会让分析结果用聊天口吻而非结构化评估，且记忆 Advisor 可能导致用户间数据串用（隐私事故）。

**方案**：在 `ChatClientConfig` 新增 `analysis-ai` Bean——用 `OpenAiChatModel` 直接构造，无默认 system、无 memory advisor，专做结构化分析。

### 3. 必须先补 MyBatis-Plus 分页拦截器（前置依赖）
**问题**：项目无 `MybatisPlusInterceptor` 配置，现有 `selectPage` 不加 LIMIT，所有分页接口在高数据量下会 OOM。

**方案**：本模块第一步先补 `MybatisPlusConfig`，配 `PaginationInnerInterceptor(DbType.MYSQL)`。这是地基，不补后面预警分页接口也是坏的。

### 4. 关键词放数据库表 + 启动加载到内存
**方案**：建 `alert_keyword` 表（含 keyword、category、risk_weight、status），启动时 `@PostConstruct` 加载到内存 List。命中按 `risk_weight` 累加 + mood/stress 综合算分，比纯 if-else 更合理。

### 5. 邮件做双层降级容错
**问题**：用户大概率没配 SMTP，不做降级会让整个流程因发邮件失败而崩。

**方案**：
- `application.yml` 加 `alert.mail.enabled: false` 开关
- `enabled=false` 时用 `@ConditionalOnProperty` 不创建 `JavaMailSender` Bean
- `enabled=true` 时发邮件 try-catch，失败只记日志，不影响站内通知和预警记录

### 6. 预警去重 + 手动触发并发防护
- `alert_record` 加 `UNIQUE KEY uk_user_diary (user_id, diary_id)` 保证幂等
- `AlertScanService.executeScan()` 入口加 `AtomicBoolean scanning` 标志位防并发
- 通知冷却：同一用户同级别未处理预警存在时不再发通知，升级时打破冷却

### 7. 必须提供手动触发接口（演示刚需）
**方案**：`POST /api/alert/scan/trigger?date=YYYY-MM-DD` 让管理员手动触发扫描指定日期，演示时不用等凌晨。和定时任务调同一个 `executeScan()` 保证逻辑一致。

## 四、关键技术实现要点

### 1. `AlertRuleEngine`（纯函数，无副作用）
```java
@Component
public class AlertRuleEngine {
    private List<AlertKeyword> keywordCache;  // @PostConstruct 加载
    
    public AlertRuleResult evaluate(EmotionDiary diary) {
        List<String> triggered = new ArrayList<>();
        int score = 0;
        // 1. 关键词扫描
        for (AlertKeyword kw : keywordCache) {
            if (diary.getDiaryContent() != null && diary.getDiaryContent().contains(kw.getKeyword())) {
                triggered.add("keyword:" + kw.getKeyword());
                score += kw.getRiskWeight();
            }
        }
        // 2. mood_score 判断
        if (diary.getMoodScore() != null && diary.getMoodScore() <= 3) {
            triggered.add("mood_score_low");
            score += 5;
        }
        // 3. stress_level 判断
        if (diary.getStressLevel() != null && diary.getStressLevel() >= 4) {
            triggered.add("stress_high");
            score += 3;
        }
        // 4. 综合算分定级
        AlertLevel level = score >= 8 ? AlertLevel.HIGH 
                        : score >= 4 ? AlertLevel.MEDIUM 
                        : score > 0 ? AlertLevel.LOW : null;
        return new AlertRuleResult(triggered, level, score);
    }
}
```

### 2. `AlertAnalysisService`（用 analysis-ai 纯净 client）
```java
@Service
public class AlertAnalysisService {
    @Autowired @Qualifier("analysis-ai")
    private ChatClient analysisClient;
    
    public String analyze(EmotionDiary diary) {
        String prompt = """
            你是心理危机评估专家。请分析以下情绪日记的危机程度，输出：
            1. 危机等级（低/中/高）
            2. 主要风险因素
            3. 建议干预措施
            日记内容：%s
            """.formatted(diary.getDiaryContent());
        return analysisClient.prompt(prompt).call().content();  // 同步调用
    }
}
```

### 3. `AlertScanService`（事务边界精确）
```java
@Service
public class AlertScanService {
    private final AtomicBoolean scanning = new AtomicBoolean(false);
    
    @Autowired private EmotionDiaryMapper diaryMapper;
    @Autowired private AlertRuleEngine ruleEngine;
    @Autowired private AlertAnalysisService analysisService;
    @Autowired private AlertNotificationService notificationService;
    
    public void executeScan(LocalDate date) {
        if (!scanning.compareAndSet(false, true)) {
            log.warn("扫描进行中，跳过本次触发");
            return;
        }
        try {
            // 1. 查日记（无事务）
            List<EmotionDiary> diaries = diaryMapper.selectList(...);
            for (EmotionDiary diary : diaries) {
                try {
                    // 2. 规则检测（无事务，纯内存）
                    AlertRuleResult result = ruleEngine.evaluate(diary);
                    if (result.getLevel() == null) continue;
                    // 3. AI 分析（无事务，可能 10s）
                    String analysis = analysisService.analyze(diary);
                    // 4. 写库（事务）
                    saveAlertWithNotification(diary, result, analysis);

                    notificationService.sendNotificationAsync(...);

                    log.error("处理日记失败 diaryId={}", diary.getId(), e);
                }
            }
        } finally {
            scanning.set(false);
        }
    }
```

## 九、面试可讲的亮点

1. **双轨制设计**——实时 + 批量兜底，权衡延迟与性能
2. **规则引擎纯函数化**——可复用、可单测、无副作用
3. **事务边界精确**——AI 调用（10s）绝不在事务里，避免连接池耗尽
4. **幂等设计**——唯一约束 + AtomicBoolean 防并发
5. **AI 客户端隔离**——分析专用纯净 client，避免人设和记忆串用（隐私）
6. **邮件降级容错**——无 SMTP 也能跑，体现工程鲁棒性
7. **关键词可配置**——数据库表 + 内存缓存，可运营
